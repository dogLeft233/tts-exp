# 2025年TFG的响度与输入尺度处理

## 结论与选样口径

严格指LUFS感知响度匹配，2025代表性公开TFG并非普遍采用；若包含波形均值方差标准化，则消除整体输入尺度的处理已很常见。本次选择13个2025年公开代码/版本的代表模型，按默认可达推理路径计：3个−23LUFS，6个逐波形/片段标准化，4个没有所查入口的显式自适应音频电平归一化。9/13是所选公开实现计数，不是市场份额、全部模型比例或运行响应统计。闭源产品内部不公开，未纳入。

用官方默认分支历史查询`commits?until=2025-12-31T23:59:59Z&per_page=1`固定每仓库年末前最后可达commit，并保存tree/source正文；所有13个pin的实际committer date均在2025。不能拿2026分支HEAD的新增LUFS反写2025实现。模型范围按2025实际公开版本而非仅会议年份：Sonic/FLOAT/Hallo3预印本在2024、推理代码或主要版本在2025；MuseTalk1.5/LatentSync1.6为2025版本；EchoMimicV3于2025-08开放代码/模型，虽后来AAAI2026仍计2025。不是所有同年论文都被穷举。

## 判别口径

- LUFS：依据当前语音感知响度，实际执行目标电平匹配。本次正例目标−23。
- 波形标准化：按当前音频/当前片段估计mean/variance，减均值除标准差；可消除多数整体gain，但不是匹配某个LUFS。Processor存在还须查实际checkpoint配置。
- 固定log-Mel映射、除32768、固定数据集affine：本表不计作自适应波形电平归一化。
- 网络内部LN/GN/BN另层分析，不按模块名称给整条路径归类。图像VAE的do_normalize=False、图像Normalize以及文本normalizer均不算音频处理。

## 年份和版本最容易混淆的点

1. LongCat v1是2025-12版本，默认中文wav2vec2并有−23LUFS；2026 v1.5换Whisper-large，前置LUFS仍单独存在，不能用1.5倒推2025编码器。
2. EchoMimic V3是2025公开、wav2vec2-base-960h/True；本项目历史EchoMimic V2是Whisper，不继承其前端判断。
3. Sonic、FLOAT、Hallo3不能因arXiv2024就从2025主要公开实现中静默剔除；反之AAAI2026名头也不能把2025已开放的EchoMimicV3挪到2026首次开放样本。
4. 本表13个与[[2026年TFG的响度与输入尺度处理]]的10个样本不是配对调查，不能仅凭计数比较作行业增长趋势检验。

## 对当前实验的意义

2025已经存在三种不同接收合同：显式LUFS、逐输入标准化、Whisper默认保留前端电平差异。源代码路径中“没有LUFS”不等于电平能穿过整个模型，也不等于加大音量会提高Sync-C。[[53-encoder-input-normalization-ablation]]已在独立编码器同权重对照中显示7/8关闭输入norm后恢复方向响应、W2vBERT仍由后续逐帧LN消除log增益；它不代替本表13个TFG的实测。训练、驱动、评价三端仍须分开。
