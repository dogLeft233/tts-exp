# 研究服务器缓存清理与可恢复归档

## Context

用户授权用百度网盘解决服务器空间，并继续完整机制实验。服务器overlay约3.3GB、autodl-tmp约2.7GB可用；WORLD的1920个参数NPZ占6.522GB，生成评估仍需空间。本地CloudDrive B盘约1.27TB可用。既有缓存迁移已完成，两个旧conda-pkgs路径是指向迁移树的symlink，复制校验receipt匹配，不能重跑旧finalize删除操作。

## Choice

对两棵已封存cache-migration树内的conda repodata JSON/solv和未完成partial下载，可以按独立逐文件清单核验后清理。保留URL/锁/未知文件；不删除环境、解压包、权重、原始数据或实验产物。每个删除目标要求普通文件、精确允许路径、位于已解析固定cache root内、当前bytes/SHA匹配、无活动安装器，使用逐文件unlink并记录成功与失败、释放量和剩余文件。不得递归删除computed目录。

科学产物可以经SSH流式归档到本地C盘，避免服务器先生成一个大型tar；再复制到B盘并读回同SHA。要求完整member清单、每member SHA、整个archive SHA及全部恢复核验，保留run/source/seal/执行记录。WORLD NPZ释放还必须先通过完整80对/160contexts独立物理EVAL QA，并核验GPU evaluator只依赖保留的WAV而不依赖NPZ。挂载copy完成仅表示挂载可读，不声称云端同步完成。未达到条件时保留服务器科学副本。

## Rationale

conda缓存是可重新下载的数据；hash/path/installer门限使清理范围可复查。实验输出承载科学证据，必须可恢复并与密封账本一致。流式归档将临时空间放在本地，避免再次挤占服务器。已有norm08完整独立消费，可作为另一归档候选。

## Alternatives

只清理.conda/.tar.bz2并不能释放当前空间，因为实际清单没有这些包。直接删除科学NPZ能腾空间但会损失可复现证据。仅把文件复制到挂载盘而没有逐member恢复核验不足以允许释放原副本。

## Observations

- [decision] 核验可再生缓存后逐文件清理；科学副本仅在完整归档与恢复核验及独立QA后释放。
- [rationale] 优先清理可再生数据，归档将临时空间转移至已授权本地和网盘。
- [alternative] 直接删除科学参数、递归删除迁移树或仅凭copy成功删除原件均不采用。
