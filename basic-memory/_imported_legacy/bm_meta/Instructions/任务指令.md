# 任务指令

本笔记覆盖 tts-exp 项目里任务跟踪的规范。任务 = 需要完成的多步工作, 跨会话存在。

## Folder map

- `Tasks/` — 任务笔记
- `Tasks/Task Board.md` — 任务索引(未完成任务的看板)
- 写入用 `directory="Tasks"`(大写 T);permalink 全小写 (`tts-exp/tasks/...`) 是正常现象,严禁照抄进 directory 参数

## Schemas in play

| 类型 | Schema | 必填观察 |
|:--|:--|:--|
| Task | `Schemas/Task.md` | status |

## 命名约定

- 任务标题: 短祈使句,如 `修复 SyncNet min_track 静默失败`
- status 词汇: `open → in-progress → done`;blocked 是持有态。**只允许这四个词, 禁用 "active" 等自造值**
- 日期格式: `Month D, YYYY`

## 任务格式 (OpenSpec spec 风格)

任务正文包含 `## Requirements` 节, 采用 OpenSpec spec 格式 (与仓库 `openspec/` 的 spec-driven schema 一致):

```markdown
### Requirement: <一个可验证的 SHALL 语句>
<可选补充上下文>

#### Scenario: <场景名>
- **WHEN** <条件>
- **THEN** <可验证的预期>
```

规则:

- 每个任务 ≥ 1 个 Requirement, 每个 Requirement ≥ 1 个 Scenario
- SHALL 语句必须可验证 — 写 "产出 X 且 gate Y 通过", 不写 "优化 X"
- **done 判定 = 所有 Scenario 的 THEN 逐条验证通过**; 有未满足项就写 [blocker] 观察, status → blocked
- 格式与 `openspec/changes/<name>/spec/*.md` 的 delta 格式兼容, 内容可双向搬运
- 简单流程任务 (如部署一个模型) 写 1 个 Requirement/Scenario 即可, 不强制铺满

## OpenSpec 联动

任务源自或执行一个 OpenSpec change 时:

1. Observations 加 `[openspec] openspec/changes/<change-name>` (纯路径, 不是 wiki-link)
2. tags 加 `openspec`
3. BM status 与 `openspec/changes/<name>/tasks.md` 的 checkbox 保持同步 — 勾选即更新对应观察
4. change 归档后, BM 任务补 close_date 并收口

## 工作流

1. **新任务**: search(防重复)→ 建 Task 笔记(open), 按 `Templates/Task Template.md` 写 Requirements/Scenarios
2. **开始**: status → in-progress
3. **完成**: 逐条验证 Scenario THEN → status → done + close_date 观察 → 从 Task Board 移除(旧任务由搜索找到)
4. **Task Board 更新**: 整表重写(read → 改 → overwrite),不做片段编辑

## 结构规则

- 每个任务笔记只有**一个** `## Observations` 节 — 更新走 edit/重写, 禁止 append 出第二个 Observations 节
- status 观察全笔记**有且仅有一条**; 历史结论写成 [result]/[decision]/[progress], 不再写 [status]
- frontmatter 的 status 字段与 [status] 观察保持一致

## 领域规则

- 任务必须关联父实验(`- project [[Experiment]]` 关系字段),除非是纯流程任务
- 任务板只放未完成任务;done 任务不进板
