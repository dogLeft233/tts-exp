# 记忆使用速查

给用户看的速查卡 — 记住这几句话就能用好 Basic Memory。

## 你可以说的话

| 你说 | 会发生什么 |
|:--|:--|
| "记一下:今天搞定了 XXX" | agent 搜索已有笔记 → 新建或更新对应笔记 |
| "我们上次关于 XXX 的结论是什么?" | 先搜 tts-exp 项目记忆,没有再搜 main 全局记忆 |
| "把这个任务加到板子上" | 建 Task 笔记 + 更新 Task Board |
| "记录这个踩坑" | 建 Pitfall 笔记(以后同症状一搜就有) |
| "这篇论文记一下" | 建 Paper 笔记,挂到研究主题 |
| "把增强头评估的结论更新一下" | 读全文 → 更新 observations |
| "切换到 main 项目" | 之后的操作落到全局记忆 |

## 核心规则(agent 遵守)

1. 会话开始先读 Startup Router,按分发表加载指令
2. 建笔记前必先搜索,存在就更新,不重复建
3. 每次调用显式传 project
4. 覆盖前先读全文,changelog 行追加不编辑
5. 目录大小写严格:Experiments/ Research/ Tasks/ Decisions/ Pitfalls/ Papers/ ToolNotes/
6. **凭证永不写进笔记** — 只走环境变量或 ~/.secrets/

## 笔记类型速查

| 类型 | 位置 | 必填 |
|:--|:--|:--|
| 实验 | Experiments/ | status |
| 研究主题 | Research/ | status, question |
| 任务 | Tasks/ | status |
| 决策 ADR | Decisions/ | date, status |
| 踩坑 | Pitfalls/ | area, symptom |
| 论文 | Papers/ | status |
| 工具备忘 | ToolNotes/ | tool |

## 维护节奏

- 每周:看一眼 Task Board 和最近的笔记
- 每月:`schema_diff` 查结构漂移,`schema_validate` 验证
- 规则变化:改指令笔记(带 changelog),不要静默偏离
