# 纯增益编码方向的跨说话人共性补算

## 问题与范围

用户追问：幅度干预通过编码方向影响生成，是否已证明不同语音的方向改变量一致？历史40人RAW/FIXED四格验证了方向分量的生成评分响应，但没有直接给出跨样本方向一致性。此次仅复用报告46新20人每人一句的RAW、±3、±6dB编码，进行事后描述性CPU计算，0新模型前向、视频、评分或训练。

## 方法

逐帧先将512维编码z单位化为u=z/||z||，再计算du=u_gain−u_raw，剥离向量长度。每句取du时间均值，两两比较20个句均值方向；190对不当190个独立样本。留一说话人：用其他19人的句均值等权平均定义参考方向，测试被留出人的句均值及逐帧du。负增益在跨人统计时反向，统一表示向更高电平变化；加减剂量路径明确比较du_plus与−du_minus。

全2155个编码帧均保留；另报告每句首尾各去20编码帧的敏感性，共1355帧。这不是SyncNet guard20查询支持，未按端点重选时间范围。所有范数/差向量均非退化，无删除、零值替代。没有音素标签分层、bootstrap或显著性结论。

## 结果

| 指标 | 全编码帧 | 首尾各去20编码帧 |
|---|---:|---:|
| +3dB：跨人句均值两两方向cos平均 | 0.812192 | 0.797210 |
| +3dB：190对cos最小/最大 | 0.571348/0.954167 | 0.474656/0.946488 |
| +3dB：留一人句均值与其余19人方向cos平均 | 0.895789 | 0.886911 |
| +3dB：逐帧与其余19人方向cos，先句内再人等权 | 0.393529 | 0.456820 |
| +3与+6dB同帧du方向cos，人等权 | 0.971591 | 0.977191 |
| +3与反向−3dB同帧du方向cos，人等权 | 0.879980 | 0.900967 |
| +6与反向−6dB同帧du方向cos，人等权 | 0.756355 | 0.789581 |

所有四非零剂量的句均值两两cos均为正，全支持平均分别+3=.812192、+6=.814887、反向−3=.821634、反向−6=.831840。+3句均值矩阵未中心化SVD第一轴平方量占82.542%，但这是20个句均值的量，不是全部逐帧变化的解释比例，不能称82.5%的生成收益。

结果支持同一模型内存在跨语句的电平方向共同分量，同时保留明显逐帧变化。同帧+3/+6高度相似，正负6dB反向匹配低于±3，提示有限幅度响应并非严格直线往返；不能据此单独识别clip、激活或其它非线性来源。

## 对已有结论的影响

这次计算的是方向改变量，不是处理前后编码本身的cos。共同几何趋势不等于共同质量收益：报告46中+3dB仍有5/20说话人Sync-C下降。不能证明该平均轴充分复现真实幅度干预，更不能外推SyncTalk、MuseTalk、Ditto或其他身份。也不能给编码轴赋予“发音更清楚”等未经检验的语义。

下一候选应先在训练/校准人上定义共同轴，在留出人上检验它能否预测逐帧变化，再将共同分量与剩余分量分开做保范数生成对照；当前仅提出，不执行新GPU。纯加法、切空间投影、共同旋转是不同算子，须明确约束，不能混称同一种方向移植。

## 核验与复现

脚本 runs/encoder_direction_commonality_20261018/analyze.py；原始派生统计 result.json；核验 qa.json。100个编码文件SHA逐一匹配报告46原encoder_manifest.json；另用逐对循环和einsum重算+3两种支持的主cos均值，最大差1.1102230246251565e-16。首次系统python缺NumPy，仅导入失败；改用桌面自带Python后计算成功，无新安装。未运行源码测试或独立科学复现。

## Observations

- [result] 20人+3dB句均值方向两两cos=.812，190/190为正；留一人cos=.896；逐帧共同方向cos=.394。
- [conclusion] 有跨人电平方向共同分量，但逐帧方向与有限剂量路径并非统一常向量；尚无共同轴生成因果收益证据。
- [verification] 100原数组SHA匹配；独立主公式复算误差1.11e-16。
- [next_step] 若继续此问题，先用校准/留出设计评估共同轴对逐帧变化的解释，再决定最小保范数生成因子实验。
