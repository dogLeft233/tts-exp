# 原生构音干预的局部支持与奇偶响应诊断

## 问题与动机

[[41-native-articulatory-response]]已控制输入方向/norm/Gram并通过六格zero功能控制，但全局高度方向仅1/6格完整响应；评分与功能变化分离。一个需要直接检查的解释是：全局anchor margin增加时，候选同时远离recipient原生空间中同phone的自然局部支持，decoder对这类变形的响应大于有符号构音增益。这只是待检验解释，不能预先写成off-manifold已证实。

先用现有数组区分这个解释和“即使局部支持保留，decoder也没有稳定同号响应”。不启动新GPU、训练、API或编码，不改变报告41任何主门。

## 限定设计

1. 从现有三臂口部effect直接计算全部六格raw/z Cp/Hp：odd=(plus−minus)/2；even=(plus+minus)/2−zero。odd描述有符号响应，even描述正负共有变化；不设posthoc成功阈值、选格或翻方向。
2. 复用accepted自然9FIT原生token计算、MFA与当前rotation三臂真实数组/receipt。沿原partial IPA/basephone/core定义，每个被旋转token的单位方向均值q，分别求每个FIT speaker中同basephone token的最小cosine distance，再对有支持speaker等权取median；排除target speaker，至少3其他speaker。
3. 全部实际被旋转token报告zero/plus/minus距离及delta、原signed height margin、support数和无法测量项；不得挑phone/dose、增加anchor/样本或改计算定义。各模型分别描述，不把token视为独立speaker推断。
4. 原Muse Luna复用accepted helper、自然数组/原MFA完成一次CPU执行，ROOT独立从实际数组/MFA重建局部距离和奇偶值；没有新依赖或源码追溯支线。

## 实际结果

完整结果与6格数值表已并入 [[41-native-articulatory-response]] 的posthoc CPU补充节。21个实际旋转token均≥3FIT人同phone支持，原171phone rows全保留。Muse plus全部6个token距离缩小，Hp却未稳定提高；当前nearest-cosine尺度的统一远离自然支持解释与结果相反。Wav z Hp odd两句为−0.049852/−0.032192，Muse为+0.007447/−0.294807，Ditto为+0.150001/+0.100369；Ditto S24 even−0.111784抵消odd。无posthoc成功阈值。

## 证据界限与预算

这是报告41之后的posthoc机制诊断。nearest-cosine不是实际高维流形距离，不将此结果推广为全部分布变化已排除。只有既有数组CPU计算，没有新模型/渲染/编码/API/训练/实现测试。下一优先定位接收端的局部响应，保持小预算。
