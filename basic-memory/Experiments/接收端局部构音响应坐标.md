# 接收端局部构音响应坐标

## 当前理论问题

[[41-native-articulatory-response]]表明输入margin可控而原冻结输出功能增益不稳定；[[42-output-owned-native-coordinate]]随后修正Muse输入所有者，得到双人功能控制，但full评分未提高。[[原生构音干预的局部支持与奇偶响应诊断]]发现Muse正方向更近同phone自然参考仍功能失败，下一问题转向接收模型如何读取局部输入，而不是继续对global phonetic metric加规模。

先拆现有曲线的high/low贡献，判断哪个音素/局部语境出现响应反向。这个定位只花一次已有JSON CPU计算，不重做距离或原始科学资格；暂无新GPU预算。

## 冻结的最小定位

- 直接用已验effect03的每token17点raw/z aperture曲线，匹配rotation receipt的phone_index。原两句、三模型、原S17与旧RMS p不变；全部18个实际视觉支持token都报。
- 类别符号s：a为+1，i/y/u为−1。class-signed odd=s*(y_plus(p)−y_minus(p))/2；同时报even=(y_plus(p)+y_minus(p))/2−y_zero(p)、三臂原值与native signed margin odd=(margin_plus−margin_minus)/2。
- native margin分母>1e-9时报告class-signed output odd/native margin odd的描述gain；否则null。raw/z均保留。Wav另外3个旋转但视觉支持不足的token显式缺失，不补样本。
- 无阈值拟合、选phone、翻符号、重选p或池化token推断；结果决定下一坐标假设是否值得独立小预算干预。

## 重要边界

原干预同时移动多个token，decoder存在重叠上下文。因此该比值只是joint干预下的局部观察响应，不能称为隔离的partial causal derivative或完整Jacobian。native可控仍不代表waveform可达。
