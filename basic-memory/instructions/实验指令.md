# 实验指令

## 搜索过去实验

回答实验路线、结果或机制问题前，先在 tts-exp 用 Basic Memory 全文检索（MCP 中使用 search_type=text；不要依赖默认 hybrid 语义检索）。准备多种查询变体：中文标题、英文 slug、编号和结果关键词，例如 MFA-linear、ΔSync-C、音素、谱形、响度、replacement、natural audio。

搜索必须覆盖两种位置：
- Experiments/：记忆侧的新实验与探索方向，描述性标题，无编号。
- docs/experiments/：仓库正式报告的记忆镜像，按 NN-slug 命名；既有镜像只读。

可按 note_types=["experiment"] 或 metadata_filters 的 status 缩小范围。命中后 read_note 读全文；低分、只有总览页或没有直接命中时换查询变体再搜。需要关联路线时用 build_context 展开 relations。项目内无结果或确实需要全局结论时，再检索 main。

## 记录状态与结论

实验笔记应标清问题、冻结设计、cohort、实验单位、评价端点、支持集、已运行阶段、数值、统计区间、工程验证、科学状态、限制和下一步。明确区分：
- SPEC_ONLY：仅有方案。
- IMPLEMENTED：代码在仓库，尚无可核验 run 结果。
- CONCLUDED：运行产物与独立复核支持写出的结论。
- CONTROL_FAILED、DEPENDENCY_BLOCKED、UNMEASURABLE：分别保留工程控制失败、依赖阻塞、无法测量；不能写成科学阴性。

SyncNet 的分数或特征变化属于评价器证据。只有独立视觉测量或合格盲评满足预设标准后，才可以讨论视觉运动变化或感知同步；不能把 Sync-C 的变化直接称为嘴型更准确。

## 写入与维护

所有项目内容写入 Basic Memory 项目 tts-exp，不写入 main。探索和进行中的实验写在 Experiments/；正式结论遵守仓库 docs/experiments/ 的编号和报告规范。工程决策写 docs/adr/，部署、分数表和参考资料分别写 docs/deployment/、docs/results/、docs/reference/。

不写 *_progress_*.md 或等价的进度日志。跨会话追踪未完成工作使用 Task；代码与协议时间线以 Git 为准。新增或修订笔记时遵循对应 schema，写入后 read_note 读回核对，必要时检查 relations 与索引。
