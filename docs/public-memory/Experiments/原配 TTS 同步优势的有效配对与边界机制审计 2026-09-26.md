## Observations

- [status] concluded
- [question] 原配TTS−N Sync-C优势在只删除虚构embedding padding、改变真实首尾/内部权重后如何变化？分开无效配对、真实端点上下文、时间尺度与有效语音表征，不把guard效应预先叫padding假象。
- [phase] 接口审计后理论端已冻结执行：动态云74 source PCM为主队列，静态原74eval为复核，Ditto47 source/legacy仅单speaker描述；联合长度为主，旧长度桥接。所有队列报告guard0/valid-pair/guard15/guard20及同支持与最大支持，I/E/P闭合和原padding、valid-pair的区曲线×区权重4格Shapley；Q1/Q2分别分解后条内平均；speaker等权20k bootstrap99CI seed20260926。不报告贡献百分比。
- [endpoint-discovery] static worker先提取F−4视觉窗口与floor(S/640)−5音频窗口，再取min；官方evaluate联合循环为min(F,floor(S/640))−5。视频限制的static缓存因此多1行。旧复核证明calc_pdist矩阵公式一致，没有证明整个pipeline联合端点一致。
- [decision] 理论端要求新主分析采用官方计分公式及联合长度、保留现有裁剪/解码/JPEG固定前端；旧缓存长度只作旧报告精确重放。修正长度必须截短两模态后重建末端音频零padding，不能仅删除矩阵末行。不称整个官方pipeline相同。
- [proposal] CPU优先缓存重算31lag距离曲线，先重放旧报告；新联合长度上比较原padding平均、逐lag真实有效pair均值、共同全lag有效行、guard20；在有效pair内分首20/中间/尾20，曲线按精确计数闭合及预定等权重反事实，再算median−min并报B/D。所有N/T配对支持与speaker权重一致，99CI；不把非线性C当各分量线性相加。
- [assets] 定位static100 N/C/Q1/Q2的tts_chinese_instance_primed_20260926、dynamic cloud74的tts_pcm_residual_20260926、Ditto47的tts_clock_cross_20260926。Ditto47只有1个音频speaker，不能冒充speaker独立CI。
