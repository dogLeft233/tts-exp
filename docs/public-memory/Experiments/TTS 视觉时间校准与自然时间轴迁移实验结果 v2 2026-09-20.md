# TTS 视觉时间校准与自然时间轴迁移实验结果 v2 2026-09-20

## 实验问题

在修复 v1 的静音词层误判、逐 phone 支持侵蚀、控制方向判定和独立复算问题后，TTS 与自然音频的视觉动作时间差异能否进入原定的 native 比较与替换生成实验？

## 协议与实现

- 协议：`tts_visual_timing_v2`；正式运行：`runs/tts_visual_timing_v2/`；smoke：`runs/tts_visual_timing_v2_smoke/`。
- 修复涉及 `scripts/experiments/tts_visual_timing.py`、`tts_visual_timing_metrics.py`、`tts_visual_timing_worker.py`、`check_tts_visual_timing.py`，并补充对应回归测试。
- 纯测试结果：15 passed；相关脚本 `py_compile` 通过。
- 独立 checker 重新从原始特征、PTS、事件和控制映射复算，最终 `runs/tts_visual_timing_v2/validation.json` 为 PASS；校准 28 个 cell、64 个正式特征/事件均有完整台账。

## 运行结果

### 诊断与 smoke

- 12 对正式 TextGrid 的诊断全部完成，覆盖率约为 N 0.910–1.000、T 0.924–1.000；正常静音不再被误报为缺 words tier。
- 连续支持块被按真实 gap 分开，避免逐 phone 两端各扣 240ms 造成的假性无支持。
- smoke 校准 I/O 和 checker 均通过，但按协议标记 `science=NOT_TESTED`，不能作为科学证据。

### 正式校准

- 4 条固定校准记录中 3 条 PASS，1 条 `INSUFFICIENT_SUPPORT`（`REFERENCE_EVENT_COUNT_LT_2`）。
- 总门要求至少 3/4，因而校准科学状态为 `SUPPORTED`，可以进入 native 阶段。
- 这只证明 v2 的视觉时间代理对已知控制扰动有可测响应，不等于证明嘴型真值或 TTS 机制成立。

### Native 与原方案后续

- 12 条 native 样本全部执行；只有 5/12 条形成可测 source 支持，共 11 个参考事件，3 条 B_V 为正。
- 可测组 B_V 均值为 65.1507 ms；98.333% bootstrap CI 为 [-0.0363, 158.8571] ms。原门要求至少 8 个 source 和 16 个参考事件，实际未满足，native gate 为 `NO_CLEAR_SUPPORT`。
- 因 native 支持门未通过，Wav2Lip/Rubber Band replacement generation 按协议 `SKIPPED_BY_GATE`，不是工程异常；没有把空预测或检测失败当作正常结果，也没有降低门槛。

## 科学结论与边界

本次修复已经解决了 v1 的工程阻塞：静音映射、连续支持、控制方向、协议缓存身份和校准独立重算都能工作，且正式校准达到 3/4。原方案随后确实继续执行到 native，但当前 12 条队列只有 5 条可测，支持不足使 B_V 的点估计仍跨零，不能判断 TTS 是否改变了嘴部动作时间，也不能判断 TTS 对 Wav2Lip 生成是否有因果收益。

因此当前结论是：测量链路已修复并成功校准，native 机制证据仍不足；generation 合法停止。下一次实验需要先固定一组能满足原 native 支持门的样本/输入条件，并重新预注册，不能把本次停止改写成 TTS 阴性或嘴型没有改善。
